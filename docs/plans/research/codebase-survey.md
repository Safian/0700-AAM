# Kick codebase survey for a piano CLAP plugin (2026-11-04)

Read-only survey of worktree `kick-plans` (HEAD 35fce454). All paths relative to the repo root.
Abbreviations: KP = `Kick/modules/engine/audio_program`, AFM = `Kick/modules/engine/audio_file_manager/source`.

## 1. Sample engine (KeygroupProgram and relatives)

### Class structure
- `KeygroupProgram` (`KP/synth/keygroupProgram.h:28`, `KP/synth/KeygroupProgram.cpp`) derives from `ISynthObject` (`KP/synth/iSynthObject.h`). It is the audio-side object; `MTKeygroupProgram` (`KP/source/mt_audio_keygroup_program.h:28`) is the project/model side that owns the clips and forwards note calls to it.
- Voice = `AVoice` (`KP/synth/audio_voice.h`), derived from `ISynthVoice` (`KP/synth/iSynthVoice.h:22`), which derives from `ASliceRenderer` (`AFM/audio_sound_renderer.h:26`). Sample data = `ASound` / `ASoundSlice` (`AFM/audio_sound.h`).
- Model: `MTIKeys` (`Kick/modules/engine/audio_engine/engine/mt_audio_interface_types.cpp:299`) = clip (zone) with `keyNote`, `minNote`, `maxNote`, `polyPhony`, `muteGroup`, `semi`, `fine`, `gain`, `pan`, `samplePlay`, `layerPlay`, LFO, pitch/filter/amp envelope fields (`mt_audio_interface_types.h:353-470`). Each clip has `MAX_LAYERS = 4` layers (`mt_audio_interface_types.h:52`), each `MTILayer` with `source`, `slice`, `velStart`, `velEnd`, `offset`, `tailStart`, `tailLength`, `isLooping`, randomisation (`:333`).
- `KeygroupSampler` (`Kick/modules/engine/objects/sampler/KeygroupSampler.cpp`) is the OLD sampler path: still compiled (`objects/objects.cpp:47`) but nothing instantiates it (no reference outside its own files). It contains CYCLE/RANDOM layer selection and passes LFO/envelope to its voice; the live path (`KeygroupProgram`) uses none of that.

### What the live engine does (`KeygroupProgram::noteOn`, `KP/synth/KeygroupProgram.cpp:58-125`)
- Zones: collects clips with a sound on any layer; one sample -> chromatic, root = MIDI 60 for the whole keybed. Several samples -> pick the clip with the lowest rank = (in-zone ? 0 : 1000) + |note - keyNote| (`:~86-93`); `root = keyNote`. Exactly ONE sample plays per note (no zone overlap, no crossfade between zones).
- Pitch: `2^((Note-root)/12)` as `AVoice::setPitchRatio`; also multiplied by program pitch and bend (`audio_voice.h:process`: `master.pitchRatio * master.bendRatio * pitchRatio`), plus slice `semi/fine` and rate conversion (`ASoundSlice::retune`, `audio_sound.cpp`). Pitch bend is fixed +-2 semitones (`mt_audio_iprogram.cpp` pitch-wheel branch).
- Velocity layers: only if `layerPlay == VELOCITY`: layer whose `velStart <= vel <= velEnd` (inclusive; the old sampler uses `<` on the end); voice then plays at velocity 127 (full gain). Any other `layerPlay` -> first layer with a sound. So CYCLE and RANDOM (round-robin) are NOT implemented in the live engine. Hard switching of layers: no velocity crossfade/interpolation, max 4 layers.
- Loop: `ASoundSlice.isLooping`, `loopStart/loopEnd` (`audio_sound.h:76-95`), forward/backward/reverse variants (`audio_sound_renderer.cpp`). `isCrossFade` exists as an attribute (`audio_sound.cpp:182`) but the renderer never reads it: no loop crossfade. Loop points are per slice (SLICE element), not per layer.
- Interpolation: LINEAR (`audio_sound_renderer.h:interpolateSample`, `interpolators.h:linearInterpolator`). Cubic/Hermite/Spline5 functions exist (`interpolators.h`, `PREFERRED_INTERPOLATOR = CUBIC`) but are unused by the renderer.
- ADSR / filter / LFO: `AVoice` has none. They exist only in `DrumVoice` (`KP/synth/drum_voice.cpp`, `AudIO/AudIO/Dsp/adsr.h`, `filter.h`, `lfo.h`) used by the Drum program. Keygroup clips store envelope/LFO fields in the model, but `KeygroupProgram` ignores them.
- Attack: voice gain ramps over 2 ms (`ISynthVoice::prepareToPlay` `gain.reset(sr, 0.002)`, `noteOn` sets target = vel/127, linear).
- Release: `ISynthVoice::noteOff` -> `ASliceRenderer::stop()` -> `finished = true` -> HARD CUT, no release fade, no tail (`iSynthVoice.cpp:noteOff`).
- Note-on/off routing (`KP/source/mt_audio_iprogram.cpp:noteProcess`, ~l.262-380): `samplePlay`: ONE_SHOT = note-off ignored (sample plays to its end), NOTE_ON = note-off releases, NOTE_OFF = inverse. CC64 sustain via `SustainState` (`KP/source/mt_sustain.h`) applies only to NOTE_ON samples and live input only. `make_piano_project.py` writes `samplePlay="0"` = ONE_SHOT, so for the generated piano the pedal and note-off have no effect.
- Polyphony: `POLYPHONY::MIN=1, MAX=64, DEFAULT=16` (`AudIO/AudIO/Includes/Constants.h:37`). `KeygroupProgram` pre-allocates 64 voices (`KeygroupProgram.cpp:36-39`, each with a 2 x 480 float temp buffer). Per-clip `poly` limits simultaneous voices per NOTE (`getFreeVoice`, `iSynthObject.cpp:~70`). Voice stealing is an empty `else { // Steal voice. }` branch: when all 64 are busy or the per-note limit is reached, the note is dropped. Same note retriggered stacks voices (ONE_SHOT) up to `poly`.
- Mute groups: `muteGroup` -1..32 (`kick_Constants.h`), handled in `MTIProgram::forSamplesInSameMuteGroup`.
- Block size / rate: `AUDIO_SAMPLE_RATE 48000`, `AUDIO_BLOCK_SIZE 480` (`Constants.h:7,10`); the audio bridge adds one 480-sample block of latency (`Kick/README.md`).

### Memory / streaming
- All RAM, no disk streaming (grep for streaming readers in `Kick/modules/engine`, `AudIO` finds none). `ASound::resample` (`AFM/audio_sound.cpp:~65-120`) reads the whole file through `juce::AudioFormatManager` (`registerBasicFormats()`, `AFM/audiofile_manager.cpp:29`) into a 2-channel float32 `AudioBuffer` (mono is duplicated to stereo, extra channels dropped); `ASOUND_UPSAMPLE_RATIO = 1`, i.e. no conversion at load, rate handled at playback.
- Cost estimate (computed, not measured): float32 stereo = 8 bytes/frame. 25 notes x 4 layers x 14 s x 44.1 kHz is about 490 MB. A real 88-key, multi-layer piano will be several GB -> needs streaming or compression in a new engine.
- Cache `ASoundCache` (`audiofile_manager.cpp`) is keyed by path OR bare file name (`exists()` matches on `getFileName()`), so two samples with equal file names in different folders collide. `purge()` returns after the FIRST cached sound (the `return` inside the loop) - effectively broken.
- Formats: whatever JUCE basic formats read (WAV 8/16/24/32-bit and float, AIFF, FLAC, Ogg if enabled by build, platform codecs). The standalone experiment `Kick/apps/mpc_gui/main_gui.cpp:~355` reads only 16-bit PCM, so the MPC factory F9 WAVs are presumably 16-bit (not verified; the factory samples are not in the repo).

### Project format (`.kickPrj`, XML; `Kick/demos/Demo 01/Demo 01.kickPrj`)
- `<FILEMANAGER><ASSETS><FILE path="samples/x.wav"><SLICE id name loopStart loopEnd [loop reverse semi fine gain pan ...]/></FILE>`
- `<PROGRAMS><PROGRAM name type="1" id><INSERTS/><CLIPS><CLIP keyNote minNote maxNote samplePlay layerPlay gain pan [poly semi fine muteGroup ...]><LAYERS><LAYER source slice velocityStart velocityEnd/>...</LAYERS><SPLAY/><SMUTE/><LFO/><PITCHENV/><FILTERENV/><AMPENV/></CLIP>`; `type`: 0 Drum, 1 Keygroup, 2 Midi, 3 Audio, 4 Clip, 5 Plugin, 6 Cv (`MTProgramType`, `mt_audio_interface_types.h:~92`).
- `<TRACKS><TRACK id name program length ...><NOTELIST/>`.

### `docs/akai_mpc_hardware/tools/make_piano_project.py`
- Input: template `.kickPrj`, folder of MPC "F9 Grand Piano" WAVs (`Inst-Piano-F9 Grand Piano-<note> <name> <vel>.WAV`, notes 24..96 every 3rd, velocities 046/084/105/127), output dir. Copies WAVs to `samples/GrandPiano_<note>_<vel>.wav`, writes SLICE (`loopStart=0`, `loopEnd=frames`, no loop flag), one CLIP per root note (`keyNote=root`, zone root-1..root+1, outer zones extended to 0 / 127), 4 LAYERs with velocity ranges 0-64 / 65-94 / 95-116 / 117-127, `layerPlay="1"` (VELOCITY), `samplePlay="0"` (ONE_SHOT), one Keygroup program, one track. 25 notes x 4 layers = 100 WAVs.
- Separate earlier experiments (not in the CMake build): `Kick/apps/mpc_gui/main_gui.cpp` (21 F9 samples, +-1 semitone resampling, 150 ms damper release per commit message ee8fe58e) and `Kick/apps/mpc_piano/main.cpp` (ALSA additive synth with sustain pedal).

## 2. CLAP layer

- Kick contains a CLAP HOST only, not a CLAP plugin implementation. `Kick/clap_host/` = host core (`src/Host.cpp`, `src/Discovery.cpp`, `include/kick_clap/*.h`), JUCE session/panel (`juce/PluginSession.*`, `juce/PluginPanel.*`), scanner `tools/scan.cpp`, bench tools, tests; Kick program type "Plugin" = `MTClapProgram` (`KP/source/mt_audio_clap_program.*`).
- The only `clap_plugin_t` implementations in the tree are test fixtures: `Kick/clap_host/tests/Fixture.cpp` (12 descriptors; instrument/effect) and `Kick/tests/platform/MockClapSynth.cpp` (MIT). They are usable as a code template for a plugin skeleton.
- Host-side extensions offered (`Host.cpp:222-243`): thread-check, params, state, latency, tail, audio-ports, note-ports (dialects CLAP | MIDI | MPE), log, timer-support, posix-fd-support. Plugin-side extensions queried (`Host.cpp:320-517`): audio-ports, note-ports, params, state, latency, timer-support, posix-fd-support. NOT used anywhere: `CLAP_EXT_GUI` (no `clap_plugin_gui`, no host gui), voice-info, note-name, audio-ports-config, tuning, preset-load, remote-controls.
- Consequence for a piano plugin: Kick does NOT embed plugin editors ("Native plugin editor embedding ... not implemented", `clap_host/README.md` "Deliberate limits"). Inside Kick the plugin is controlled through generic parameter rows + 4 knob macros (`PluginPanel`) and opaque state (state extension required for project recall). A custom plugin GUI would be visible only in other CLAP hosts.
- MIDI into the plugin: `MTClapProgram::noteProcess` forwards every 1-3 byte MIDI message (notes, CC64, pitch bend, ...) to `PluginSession::midi` (`mt_audio_clap_program.cpp:35-41`, `PluginSession.cpp:149`), translated to CLAP or MIDI events according to the plugin's note-port dialect (`Host.cpp:417-476`). Sysex is dropped. No intra-buffer timestamps from the legacy tick path (host README).
- Audio: up to 16 ports / 64 channels, stereo expected on the Kick bus; mono is duplicated.
- Build: `Kick/clap_host/CMakeLists.txt` (C++17, vendored MIT CLAP headers `third_party/clap`, commit a47f6bad..., `upstream.json`; no CPM needed). Options `KICK_CLAP_HOST_ONLY`, `KICK_CLAP_BUILD_JUCE`, `KICK_CLAP_BUILD_PLAYER` (needs `KICK_CLAP_JUCE_PATH`, JUCE 7.0.12 or 8). The full app (`Kick/CMakeLists.txt`) uses CPM (`get_cpm.cmake`, `3rdParty.cmake`) for JUCE 7.0.12 (or `KICK_JUCE_PATH`) and optional melatonin_perfetto; AudIO/ComProtocol are sibling directories.
- Platforms: macOS (deployment 12.0, `CMakeLists.txt`), iOS (Xcode generator, JUCE patch `juce_ios_uiscene_7.0.12.patch`, simulator builds, app exits at launch - AGENTS.md "Known state"), Linux x86 (CI `clap-host.yml`, ubuntu-24.04 only), Linux AArch64 (cross build + QEMU smoke, `cmake/aarch64-linux-gnu.cmake` per README), Linux ARMv7 hard-float for Akai MPC Key 61 (`docs/akai_mpc_hardware/tools/armv7.cmake`, `-march=armv7-a -mfpu=neon-vfpv4 -mfloat-abi=hard`, Docker `kick-armv7-builder`), Windows (MSVC flags in `Kick/CMakeLists.txt`, desktop keyboard always on; not verified in CI). A plugin loaded on the MPC must be an armhf Linux `.clap`; host README says macOS/Windows/x86 binaries do not work on hardware.
- Does the full app run without a DAW? Yes: Kick is a standalone JUCE GUI app (`Kick/apps/kick`, `juce_add_gui_app`). `Kick/apps/kickvst` is an unused JUCE VST3 template stub (`IS_SYNTH FALSE`, 321 lines, default JUCE processor skeleton, option `KICK_VST_PLUGIN`, additionally links tracktion_engine), not a working plugin.
- JUCE has no CLAP wrapper (no "clap" match in `juce_audio_plugin_client` of the JUCE 7.0.12 cache); a CLAP piano plugin would be written directly against the C ABI (as the test fixtures) or through third-party glue (clap-juce-extensions, MIT; not in the tree).

## 3. UI

- Framework: JUCE 7.0.12 Components (software renderer) with a custom `KickLooknFeel : LookAndFeel_V4` (`Kick/modules/kick_ui_controls/source/kick_lookAndFeel.h`) and an XML theme (`Kick/assets/Default/theme.xml`, `Theme::loadTheme`, `kick_Theme.h`). No OpenGL; on the MPC the root component is painted to a `juce::Image` (ARGB 1280x800) and written to the framebuffer (`apps/kick/kick_hardware_bridge.h:36,721-754`); touch arrives in 1280x800 space and is scaled to the UI tree.
- Resolution: fixed 1024x600 logical (`kick_layout.h:31-43`: `appWidth/appHeight`, scale macros `_scaledX/_scaledY`). The MPC bridge scales 1024x600 up to 1280x800 (`kick_fallback_display.h:31`).
- Style: dark theme. Backgrounds `0xff363636 / 2B2B2B / 222222 / 1F1F1F / 151515 / 000000`, accent amber `0xffFFB608` (and `D18900`), text white `FFFFFF` / grey `B2B2B2`, selection blue `00AAEE`, meter green `1DFF00`, warning red `FE001A`. Fonts: theme names `Myriad Pro Regular.ttf` (REMOVED from the release; supply another font) with 5 sizes XS..XL (`kick_Theme.h:FONT`, `kick_Theme.cpp:123-141`), set via `setDefaultSansSerifTypeface`. Icons are SVG Drawables (`assets/Default/...`).
- Widget set (`Kick/modules/kick_ui_controls/source/`): KickSlider/GainSlider, rotary knob (Drawable-based), KickNumber, KickListBox, buttons/toggles/CyclicStateControl, KickTable, Grid, VirtualKeyboard, WaveRenderer (waveform), LevelMeter, TempoControl, AlertWindow, popups, StackedComponent, TabBar buttons. Program editors: `Kick/modules/program_edit_ui/sources/keygroup/*` (Keygroup editor, LFO, filter/env edit).
- Hardware abstraction: knobs/pads/buttons come in as `CPktMgr::HWMsg_t` via `contracts::DclSignals` (root `AGENTS.md`).
- Adding a window to a CLAP plugin: not done anywhere in the tree (no `clap_plugin_gui`). Required: implement `clap.gui` (`is_api_supported`, `create`, `set_parent`, `show`, `set_scale`, `get_size`, ...; `CLAP_WINDOW_API_COCOA` / `X11` / `WIN32`), and a toolkit that can embed in the parent handle. With JUCE: `juce::Component` + `addToDesktop(flags, nativeParent)`, JUCE message-thread integration with the host (timer-support / posix-fd-support extensions for Linux), not tested here. Kick's own look (LookAndFeel, theme XML, widgets) lives in modules that depend on the whole Kick module graph (`kick_ui` depends on `kick_ui_header, kick_ui_settings, ...`), so reuse means either linking those modules or copying the LookAndFeel/colours.
- The existing `PluginPanel` (`clap_host/juce/PluginPanel.h`) shows how a JUCE panel is composed with generic parameter rows; useful as a model for a parameter-only fallback UI.

## Hiányzik / kockázat
1. Kick has no CLAP plugin side at all; GUI extension is missing on both sides (host does not embed editors).
2. Keygroup voice has no release, envelope, filter, RR, stealing: the engine is not reusable as a piano core without major work; a separate engine is more realistic.
3. RAM-only float32 stereo loading: no streaming, name-collision-prone cache, broken `purge()`.
4. Licence: any Kick/AudIO code in the plugin forces AGPL-3.0-or-later; JUCE option (GPLv3 vs commercial) must be decided and documented; factory MPC samples cannot be shipped.
5. ARMv7 (MPC) needs an armhf build; host-side CLAP tests only run on Linux x86 / AArch64 (QEMU) in CI; macOS/Windows plugin builds are untested in this repo.
6. The b101e5b8 multisample path is unaudited on hardware; its piano project defaults to ONE_SHOT.
